# Owner integration contract — not deployed

The orchestration loop is executable with synthetic fixtures. Live execution is deliberately gated: no trusted bridge is installed/configured, no current authorized connectivity/card lease is recorded, no new fixed-length performance reference has been made. `configs/live-preparation.json` is a preparation/queue record, **not** a runnable experiment. It cannot be relabelled from the synthetic configuration to enable hardware.

The inspected runtime already provides `opentpu.host.runstate.DeviceLock` / `otpu-lock`, `opentpu.serve.api.load`, `scheduler.Worker`, `batching.BatchWorker`, request token IDs, and board cycle counters. Reuse these under the existing owner's lifecycle. `tools/f2_bench.py` starts/stops a server, while `tools/serve_bench.py` may flush cache and generate concurrent traffic; neither is safe to invoke unmodified against an interactive portal or another owner.

The future trusted bridge is a separately reviewed executable, identified by exact absolute path and SHA-256 in a new experiment manifest. It reads one JSON request on stdin and emits one trace JSON on stdout. The generator can only change `program_cache`, `prompt_runs`, `quantum` within `evolve/propose.py::SPACE`. Map them to the existing `--no-prog-cache`, `--no-prompt-runs`, and `--quantum` controls on the **owned isolated** runtime. One-client quantum may be a no-op; equal performance should be rejected, not invented. Source patch generation, shell commands and RTL are outside this initial loop.

Requirements before enabling a registry seed:

1. Verify current instance ID and role through an **already authorized** channel: card `opentpu-f2` / `i-0c78de2253f66519d`, builder `opentpu-m8a-build` / `i-0ec8d33362b3100be`, expected instance profile `opentpu-f2-ssm`. Historical IPs are not current identity evidence. Do not bypass the inherited denied SSH checks, process inspection or localhost GET through another transport.
2. Coordinate a bounded owner window with the pending portal and existing optimization owners. Under the existing canonical `/tmp/otpu/f2-0000:34:00.0.lock`, confirm all prior jobs drained and the **currently loaded** image matches. Lock alone does not exclude non-cooperating historical clients; owner reconciliation is required. Queue on busy/unknown; never kill a foreign process. No image load/reset/replacement in this setup.
3. The existing canonical lock wrapper must remain alive independently of the child evaluator, retaining its lock through all child cleanup. Verify inherited ownership using the existing runstate implementation; do not trust `OTPU_LOCK_HELD` alone. The harness preflight checks are necessary but **not sufficient**. A bridge must freshly verify the host, current image, lock, health and portal state before **every** trial and include receipts. It must never relax the canonical lock directory using `OTPU_RUN_DIR`.
4. On the builder, generate independent references for the exact performance prompts/lengths. Freeze full model/tokenizer/repacked image/runtime fingerprints and a disjoint held-out correctness suite, including repeatability and state reset. Candidate generation gets no expected answers or evaluator code as writable inputs. Preserve the historical eight-token smoke fixture as limited evidence.
5. Instrument monotonic boundaries and exact token IDs at the chosen caller boundary. Do not treat SSE chunks as tokens. Record warmup/reset evidence, CPU stage scope, full board counters, actual image/clock before and after, dependency versions, execution commit, and verified cleanup. Fail closed on fallback, ECC/correctness/health failure or changed image. Current bridge supports Gemma INT8 only; hybrid/speculation need separately qualified bridges.
6. Produce the fields validated by `evolve/evaluate.py::validate_trace`. The request strips expected token IDs before reaching a live bridge. Return raw `heldout_results` for every frozen case; evaluator compares their token IDs itself. Return `cleanup: "idle_and_runtime_restored"` only after the owned runtime is idle and settings/context restored. The live process owns no image rollback: images are unchanged.

A `75` bridge exit is reserved for a **before-action** busy result, so the coordinator may queue safely. Once any HBM write/inference starts, errors and timeouts must retain the canonical ownership session and yield an uncertain receipt for reconciliation. The harness sends SIGTERM only to the evaluator process group it created. It never forcibly kills live hardware work or releases someone else's lock. No cleanup success may be inferred from a subprocess exit.

`LiveAdapter` does not implement SSH, SSM, HTTP GET, AWS calls, tunnel creation, credentials, instance management, server publication or provider calls. It cannot itself establish authorization. Only `fixture_worker.py` is bundled as an executable evaluator today. This is the remaining runtime integration boundary, not a claim that live measurements have run.
